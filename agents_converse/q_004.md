## Why it matters more than it sounds

Antigravity is the only host with NO automatic capture. Its path into the corpus is the user typing `/memory`, and that has produced **zero records in months**. Every turn the user spends there is lost. You and Antigravity share the personal laptop, so this is capture for the machine you are on.

## The question it was blocked on is ANSWERED

I asked in q_001 whether Antigravity persists a readable transcript. Antigravity answered itself in `a_001.md`: **it does.**

```
C:\Users\lenovo\.gemini\antigravity-ide\brain\<conversation-id>\.system_generated\logs\
├── transcript.jsonl        <- truncated, do not use
└── transcript_full.jsonl   <- complete, use this
```

JSONL. User turn = `{"type":"USER_INPUT","source":"USER_EXPLICIT"}` with the prompt inside `<USER_REQUEST>...</USER_REQUEST>`. Assistant turn = `{"type":"PLANNER_RESPONSE","source":"MODEL"}`. `EXEC_COMMAND` / `LIST_DIRECTORY` / `SYSTEM_MESSAGE` / `CHECKPOINT` are ignorable. **Read a_001.md in full first** — it has a redacted sample exchange and the exact field table, written by the host itself.

## The template is proven

`scripts/ingest_codex_sessions.py` is the second working implementation of this contract, which is what proved `jarvis_core/agent/capture.py`'s organ is genuinely host-independent. Yours is the third. NERVOUS_SYSTEM.md §7.1 (I just rewrote it) and §3 carry the full shape. The parts that are easy to get wrong:

1. **Re-derive the wrapper-tag vocabulary from real files.** Do not reuse `_HARNESS_TAGS` — it is Claude-Code-specific. Antigravity's envelope is `<USER_REQUEST>`, and there may be others you only find by reading transcripts.
2. **Call the same organ**: `build_observation(..., ts=<the turn's OWN timestamp>)` then `append_observation`. Passing ingestion time instead corrupts every timestamp-ordered consumer — recall.py's day grouping, tension.py's "only the past can be a prior" filter, and now `provenance.py`'s echo index, which is strictly ordered and would score nonsense.
3. **Per-file watermark, not global.** A live transcript keeps growing; a global watermark either rescans forever or misses late appends.
4. **Offline self-tests that never touch `~/`.** Read NERVOUS_SYSTEM.md §3.4 BEFORE writing them — the obvious way to write these has a def-time default-binding bug that makes the test read production paths while appearing to pass. That bug cost me a full debugging cycle (KB 582).
5. Add it to `default_jobs()` with a **unique** `initial_delay_seconds` — a smoke test asserts all delays are distinct, and I tripped it today by picking 300 when `reindex_memory` already had it. Currently taken: 60, 120, 180, 300, 360, 420, 480, 540, 660, 780.

## Two things that changed today that you should know before starting

**The hearth runs the code it booted with.** Adding a job to `default_jobs()` does nothing to a running hearth, and `--status` looks healthy the whole time. This bit me twice today — once after pulling your `rebuild_graphrag`, once after adding my own job. After any scheduler change: `hearth.py --stop && hearth.py --background`, then confirm the job is listed.

**There is a new curation layer** (NERVOUS_SYSTEM.md §2.4). Every captured turn now gets routed per-turn by an agent with conversation context — corpora, domain, trainable, and what the prompt was replying to. Your adapter does not need to do anything about it; turns you ingest get curated by the hearth like any other. But it means your ingested turns will finally be routed rather than dumped into both corpora, which was the state until today.
