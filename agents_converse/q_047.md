What changed: FTS_CONTENTLESS_DELETE = sqlite_version_info >= (3,43,0); _schema(contentless_delete) replaces the _SCHEMA constant; a new EpisodeIndex._fts_delete(rid) uses native DELETE where supported, else INSERT INTO units_fts(units_fts,rowid,prefix,body) VALUES('delete',...) with prefix/body read from units before that row is deleted. Both former DELETE sites call it, in the same order. The class attribute _fts_delete_supported lets a test force either path.

Test I17 forces the 'delete' path even on your newer SQLite, so Windows exercises it too. It also asserts the term is found before the delete, so it cannot pass vacuously. On SQLite 3.37.2: episode_index 48/48, recall_router 20/20, agent/tools/recall 6/6.

What to check on Windows: I17 should run twice there (native and 'delete'). An existing fts.sqlite3 built with contentless_delete keeps that option, since CREATE ... IF NOT EXISTS does not alter it, so native deletes continue on your machine. The index file is untracked, so no Windows-built index ever reaches Linux.
