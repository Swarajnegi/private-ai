# Q003 — Corpus Audit: Fatal SFT Inversions in Assistant Targets, Volume Shortfall, and Raw Contamination

**From:** antigravity
**Date:** 2026-09-11T13:22:04+05:30

Following the latest pull that introduced `scripts/build_sft_pairs.py` (producing `sft_pairs.jsonl` and `sft_pairs_heldout.jsonl`), I performed a forensic line-by-line audit across all training datasets in `jarvis_data/training_corpus/`.

While `sft_pairs_heldout.jsonl` (43 pairs) is cleanly isolated and the Engineer answers are technically deep, the audit uncovered three critical blockers before any RunPod training run:

---

### 1. FATAL BUG: Shell Prompts and Role Inversions in `sft_personalization`
In `sft_pairs.jsonl`, **23 of the 73 personalization pairs (31.5%) have the ASSISTANT target trained on raw bash commands, XML tags, and user prompts**:
- **Bash Prompts:** Target Assistant output is `swara_unix@HRM5472-NEW:~/work/JARVIS$ source /home/swara_unix/work/JARVIS/.venv/bin/activate...` (`observation_queue.jsonl#2026-06-25T11:49:49+05:30`).
- **Claude XML Notifications:** Target Assistant output is `<task-notification>\n<task-id>w19fqc91s</task-id>...` (`observation_queue.jsonl#2026-06-04T14:41:25+05:30`).
- **HF HTTP Warnings:** Target Assistant output is `Warning: You are sending unauthenticated requests to the HF Hub...` (`observation_queue.jsonl#2026-06-18T14:02:25+05:30`).
- **Inverted Roleplay:** Target Assistant output is `"Hey, jarvis. Read this. I am specifically concerned with the pre-req section..."` (`observation_queue.jsonl#2026-07-13T20:33:40+05:30`).

**Mechanism:** `scripts/build_sft_pairs.py` parsed raw session turns from `observation_queue.jsonl` and placed user CLI strings / tool logs into the Assistant turn under the synthetic prompt `"Explain your own thinking on this, in your own words and at the length it deserves."`.

**Consequence:** With loss masking on assistant tokens, the model will learn to hallucinate terminal bash prompts and address itself as Jarvis.

---

### 2. Personalization Volume Deficit
`SFT_SPEC.md` calls for 200 personalization pairs. We only have 73 total in `sft_pairs.jsonl`. Dropping the 23 corrupted records leaves only **50 viable personalization pairs**.

---

### 3. Rigid Prompt Phrasing in `sft_engineer`
**254 of 324 Engineer pairs (78.4%)** start with the identical synthetic prefix: `"What do I need to know about <Heading>?"` (e.g. `"What do I need to know about cSV Ingestion Makes Everything STRING?"`). The answers are high quality, but the prompt distribution is heavily overfitted to one phrasing template.

---

### 4. Uncleaned Raw Corpora
- `engineer_corpus.jsonl`: Still contains 66 trivial chat turns <100 chars (`'yeah'`, `'Yes.'`, `'is earth flat?'`), administrative READMEs, and mid-syntax chopped code (`return DeepCloneConfig(\n ca`).
- `personalization_corpus.jsonl`: Still contains 108 records with third-person assistant commentary about the user (`"The user's manager..."`, `"PATTERN: corpus_richness_before_spend..."`).

---
