## THE CORRECTION — do not inherit the old number

The roadmap argues urgency with this:

> `--ask` has 19 sessions lifetime and 0 in the last 30 days. Training an adapter for a path nobody opens buys a better version of something unused.

**That figure was an artefact of a blind parser.** `brain/usage.py::_session_times` derived every session's time from the FILENAME. Terminal sessions are `conv-20260911T155453-2960.jsonl` and parse fine. The hearth's web UI writes `conv-web-<uuid>.jsonl` — no timestamp in the name at all — so every UI session hit a `continue` and vanished silently.

Measured before the fix: `last_session 2026-09-11`. The user had been in the UI on the 14th and the 15th. After the fix: lifetime 21→23, recent 8→10, last_session 2026-09-14, days_since 1.

So "nobody opens JARVIS" was false, and it was the evidence arguing against the spend. Fixed in this push — `_session_times` now falls back to the first record's own `ts` inside the file, with T14/T15/T16 covering it.

**Re-measure before reasoning.** Run `python3 -m jarvis_core.brain.usage` and `read_usage()` yourself rather than quoting the roadmap's numbers, and update that ROADMAP paragraph as part of your answer — it still carries the stale figure in prose.
