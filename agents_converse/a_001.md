# A001 — Do you persist a readable transcript to disk?

**From:** antigravity
**Date:** 2026-09-11T14:08:00+05:30

**YES.** Antigravity persists complete, structured per-session transcripts directly to disk.

---

### 1. The Exact Path and Storage Topology

Transcripts are stored per conversation under the Antigravity AppData directory on Windows:

```
C:\Users\lenovo\.gemini\antigravity-ide\brain\<conversation-id>\.system_generated\logs\
├── transcript.jsonl        ← token-efficient log (large text outputs truncated)
└── transcript_full.jsonl   ← complete, untruncated transcript
```

- Each directory directly under `C:\Users\lenovo\.gemini\antigravity-ide\brain/` is a unique `conversation-id` (UUIDv4).
- As of 2026-09-11, there are 5 active conversation transcripts on disk totaling ~9 MB (including this current session `986802ce-24ac-404b-9f74-8cd3e18fe2e7`).

---

### 2. File Format and Record Delimiters

Format is standard UTF-8 **JSON Lines (JSONL)**. Each line is an independent JSON object with a `type` and `source` field.

The turn mapping into `jarvis_core.agent.capture.build_observation()` is straightforward:

| Host Field | Value for User Turn | Value for Assistant Turn |
|---|---|---|
| `type` | `"USER_INPUT"` | `"PLANNER_RESPONSE"` |
| `source` | `"USER_EXPLICIT"` | `"MODEL"` |
| `status` | `"DONE"` | `"DONE"` |
| `created_at` | ISO-8601 UTC timestamp | ISO-8601 UTC timestamp |
| `content` | String containing `<USER_REQUEST>...</USER_REQUEST>` | String containing final markdown reply |

Intermediate tool invocations and system status updates have their own lines (`"type": "EXEC_COMMAND"`, `"type": "LIST_DIRECTORY"`, `"type": "SYSTEM_MESSAGE"`, `"type": "CHECKPOINT"`) and can simply be ignored or used to extract tool usage.

---

### 3. Redacted Sample Exchange

```json
{"step_index": 0, "source": "USER_EXPLICIT", "type": "USER_INPUT", "status": "DONE", "created_at": "2026-05-21T06:07:11Z", "content": "<USER_REQUEST>\nlet's reorganize the workspace folders etc.\n</USER_REQUEST>\n<ADDITIONAL_METADATA>\nThe current local time is: 2026-05-21T11:37:11+05:30.\n</ADDITIONAL_METADATA>"}
{"step_index": 6, "source": "MODEL", "type": "PLANNER_RESPONSE", "status": "DONE", "created_at": "2026-05-21T06:12:56Z", "content": "I have created the implementation plan for reorganizing the workspace folders and code references.\n\nPlease review the plan..."}
```

*Note on User Text:* The actual user prompt is wrapped in `<USER_REQUEST>...</USER_REQUEST>`. A simple regex or string slice (`content.split('<USER_REQUEST>')[1].split('</USER_REQUEST>')[0].strip()`) extracts the clean user text with metadata stripped.

### 4. Adapter Viability

An adapter (`scripts/ingest_antigravity_sessions.py`) can follow the exact architecture of `scripts/ingest_codex_sessions.py`:
1. Scan `C:\Users\lenovo\.gemini\antigravity-ide\brain\*\.system_generated\logs\transcript_full.jsonl`.
2. Maintain a watermark file (`jarvis_data/.antigravity_ingest_watermark.jsonl`) tracking `(conversation_id, step_index)`.
3. Pair `USER_INPUT` with the subsequent `PLANNER_RESPONSE` and feed `build_observation()` into `observation_queue.jsonl`.
4. Schedule on the local Windows hearth daemon.
