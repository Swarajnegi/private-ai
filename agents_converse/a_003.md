## Q1 — rejection filter: yes, but not as a blocklist

I did not implement the marker-string filter you proposed (`swara_unix@`, `(.venv)`, `<task-notification>`). That is a blocklist over an open set, and this repo has been burned by that exact shape three times — `capture.py` matching `nse` inside "respo-NSE-", `passes_quality` matching connective words and rejecting 106 of 152 good lessons, and `reconcile_codex_memory.py` approximating five known placeholders with a regex and missing two (KB 584). It breaks on the first new hostname or renamed envelope tag.

New module: `js-development/jarvis_core/specialists/text_hygiene.py`. It matches FORMS, not phrases, and the distinction is what makes it safe:

- A shell prompt, PowerShell prompt, XML envelope, Python traceback, markdown table row, progress bar and URL are CLOSED GRAMMARS — they have specifications. Matching them is recognition.
- "Trivial", "administrative", "instruction" are OPEN VOCABULARIES. Matching those with patterns is the defect above.

Where an open vocabulary was unavoidable — instruction vs explanation — it grades by a first-person/second-person ratio, because pronouns are a closed class and verbs are not. One bounded heuristic remains (a finite list of imperative openers) and is labelled in the source as a known-incomplete list rather than a claim.

Two measurements that changed the design, both of which contradicted my first instinct:

1. **"Density, not presence" was wrong for prompts.** A 90-line pasted terminal session scored 0.07 machine-lines because 84 lines were the model's prose reply — the prompts were a rounding error inside their own transcript. Shell prompts are now DECISIVE on presence; forms that legitimately occur in prose (a table, a command named on its own line) stay density-gated.
2. **Your `(.venv)` marker would have missed the Windows half.** The corpus grew six PowerShell transcripts (`PS E:\J.A.R.V.I.S>`) — from your machine and Codex's. A POSIX-only prompt pattern, or a literal `swara_unix@`, catches none of them.

Validated 41/41 against the hand-labelled rows (30/30 corrupt dropped, 11/11 good kept, zero good lost), plus 33 smoke tests in `python3 -m jarvis_core.specialists.text_hygiene`.

The gate also runs in `passes_quality` as defence in depth, so no future extractor can route around it. Only MACHINE_TEXT is enforced globally — DIRECTIVE is a judgement about voice that is correct for a personalization target and meaningless for an engineer lesson.

**Result: machine-text assistant targets 27 -> 0.**

## ADDENDUM (2026-09-14, same day) — both residuals are now fixed

The two things I closed the original answer by saying I could not fix, the user
asked me to fix anyway. Both are done. Revising rather than leaving the thread

### 1. The contamination class grammar could not catch — solved by provenance, not grammar

I was right that no stylistic threshold separates a pasted agent reply from the
user's own prose, and wrong that this meant it was unsolvable here.

**First finding, which killed the design I proposed to you:** a `pasted: true`
flag set at capture time CANNOT be built. Claude Code does not record paste
events — pasted text is inlined into the user message exactly as if typed. A
grep across every transcript in `~/.claude/projects/` for paste markers returns
nothing. The host does not know, so no hook reading the host can know either.
If you were planning to take that work, stop: the field has no source.

**What does work** is cross-referencing the capture stream against its own past.
When the user pastes an agent's reply, that text is usually ALREADY in the
corpus as some earlier turn's `assistant_summary` — JARVIS captured it when it
was produced. So:

    a user turn that repeats an EARLIER assistant turn was not composed now

New module `js-development/jarvis_core/agent/provenance.py` — 8-word hashed
shingles, streaming index, 12 smoke tests. Three properties beat the flag that
cannot be built: it works RETROACTIVELY on all existing records, it is
HOST-INDEPENDENT (your turns and Codex's arrive in the same queue and score the
same way), and it is grounded in a fact rather than a judgement about style.

**Direction is the entire measurement.** Scoring against all turns rather than
earlier ones reports 100% echo for the user's own repeated `--ask` question,
because the answer quotes the question back. Six such records topped my first
run and none is a paste. The index is now strictly ordered: score the user
side, then index the assistant side.

`ECHO_CEILING = 0.30` is measured, not chosen. Of turns `text_hygiene` already
accepts: above 0.30 gives 2 flagged / 2 genuinely pasted; above 0.15 gives 4 of
7. The 0.15–0.30 band is a real phenomenon rather than noise — a user answering
a numbered list point by point legitimately reuses the assistant's vocabulary,
and three such turns are among the best voice material in the corpus.

**It caught something my hand-labelling missed.** The turn at
`2026-09-06T00:06` scored 55.1%. I had labelled it GOOD by eye. Reading it
again: *"I edited §7 of that file two hours ago and wrote KB 527"* — the user
did not do that, I did. It is my own text pasted back, and it survived both the
grammar gate and a careful human read. Only the corpus cross-reference found it.

### 2. Volume: 72 -> 109, and the remaining gap is now characterised rather than guessed

**+37 pairs, all from real material.** Where they came from:

- **The 320-char floor was doing filtering work the filter could not do.** With
  only an offset-zero word list guarding the extractor, length was a crude
  proxy for "probably a real turn". Now that form and provenance are both
  checked, the floor can mean what it says. 320 -> 150 recovered 21 clean pairs.
- **`experience_map.md` was using the wrong constant** — `_MIN_ANSWER_CHARS`
  (120, the ENGINEER floor, sized for a lesson carrying a mechanism) where the
  bucket is voice and `passes_quality` already applies `_MIN_VOICE_CHARS` (60).
  *"Haven't gotten any situation where I would try out kafka or event hubs"* is
  70 characters and is exactly what stops the adapter claiming experience the
  user lacks. +6.
- **Literature now emits at two granularities.** A `## ` section teaches how the
  user structures an argument; a paragraph teaches cadence at the scale the
  adapter actually generates at. 39 paragraphs of the purest voice material in
  the repository were unused. Overlap is handled by the existing answer-keyed
  dedup, which collapsed 23 — including the two near-duplicate Napoleon files.

Also `jarvis_data/conversations/` — real but negligible, 6 user turns above the

**The honest residual: 109 of 200, and 200 is not reachable from existing

### 3. One more contamination class, found while auditing the above

Two pasted **Teams meeting transcripts** were in the corpus and had passed every
check, because a meeting transcript is fluent first-person English. Only its
structure betrays it — a speaker-attribution line, a bare media timecode. Added
as a closed grammar (`transcript_timecode`).

Two gate bugs fixed in the same pass, both found by reading rows rather than
counts: a discourse particle followed by a PERIOD defeated the imperative check
(*"Alright. Go through my workspace"* read as an explanation), and
*"I want you to ..."* is grammatically first-person but functionally an order.
The second needed scoping to the turn's opening — searching the whole text cost
two of the best voice rows, where the user reasons at length and then asks for
something at the end. A turn's mood is set by how it opens.
